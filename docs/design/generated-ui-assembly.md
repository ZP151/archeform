# Generated UI assembly guide

## Product outcome

Ordinary users should receive a coherent working application from their business
request. They should not need to ask for icons, colors, images, mobile layout or
missing interaction states after generation. Those are responsibilities of the
reviewed definition and renderer, not extra user-facing development steps.

The selected September 12 approval direction combines purposeful cobalt color,
warm category photography, and visible state progression. Reuse its underlying
assets and constraints in future appropriate families, rather than copying the
same purchase layout into every product.

## Assembly responsibilities

| Layer                       | Responsibility                                                                                      | What it must not do                                                             |
| --------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Requirement interpretation  | Select a reviewed business definition; clarify material business ambiguity only                     | Generate ad hoc UI source or choose arbitrary remote image URLs                 |
| Definition and Graph        | Supply real fields, roles, workflow states and declared design choices                              | Invent data, hide unsupported business requirements or mutate a published Graph |
| Private presentation recipe | Compose identity, primary action, useful record summaries, state/progress and responsive layout     | Add nonfunctional navigation or buttons for unimplemented features              |
| Material configuration      | Resolve an allowlisted original asset with dimensions, content digest, provenance and safe fallback | Treat category illustration as an actual item photograph or uploaded receipt    |
| Runtime components          | Render data and authorized actions; keep loading, error, empty, keyboard and mobile behavior        | Claim an inferred workflow path is historical audit evidence                    |

## Reusable supply contract

- Use the existing primitive and pattern keys before adding an asset. Styling
  changes belong to tokens or recipe parameters, not duplicate registry entries.
- A media-bearing slot needs a purpose, aspect ratio, focal point, decorative or
  informative alternative-text policy, local delivery strategy and missing-media
  behavior. Omit irrelevant media; do not fill every screen with stock imagery.
- A status or progression slot needs real Graph semantics. Display the current
  state and possible next step without fabricating dates, actors or completion.
- Familiar secondary actions may use only a library icon, with accessible name,
  tooltip and a minimum 44 px target. Keep words for consequential or ambiguous
  business actions such as Submit, Approve and Reject.
- Use one coherent visual system for forms, lists, detail, history and recovery.
  Preserve explicit Graph typography/colors/theme choices. Check dark mode where
  supported and reduced-motion behavior.
- Track assets, composition recipes, authored definitions, runtime families and
  usable applications as different quantities. Two reusable materials are not
  two product templates or evidence of thousands of generated products.

## Guidance for future generator changes

When extending the interpretation instructions or backend selection configuration,
describe the business outcome, roles, fields and exceptional cases. Resolve UI
through reviewed recipe/material keys in deterministic code. Do not ask the model
to write a prettier page or persist free-form styling instructions as a substitute
for an executable composition contract.

Before admitting another family, identify its primary content: appointment time,
inventory quantity, task owner/status, directory profile or product imagery.
Reuse compatible media, navigation, progress and recovery slots; introduce a new
key only for a documented semantic gap, with provenance and focused tests. Keep
the renderer usable with absent or failed media and unusually long real content.

## Fast visual regression

Use the existing task review, not a separate cosmetic audit pipeline. Record the
selected visual target and capture actual generated phone/tablet/desktop output
with realistic populated and empty states. Check resource delivery automatically,
then inspect composition and task reach against the target. A working stylesheet,
an icon count, or an accessibility pass cannot substitute for that comparison.

Reusable checks should cover image decoding and fallback, absence of unintended
remote loads, unclipped long content, accessible icon actions, real workflow
state after reload, first-action reach and supported explicit theme overrides.
Group observed visual corrections and rerun affected checks, retaining still-valid
business evidence. Do not restart unrelated audit stages for an in-scope repair.

## Findings

1. **P2 — Refresh can silently omit one conversation event while an earlier page is in flight.** `packages/compiler/src/customer-requests-presentation.ts:146-162` resets and reloads history without invalidating `historyEpoch`; `:198-206` accepts an older page whenever the request ID still matches. Reproduce with a request having more than 20 events: start **Load earlier messages** while its response is held, append a new event, select **Refresh requests**, let the new first history page resolve, then release the old page. The old cursor was calculated from the previous first page; its response appends after the new first page and can leave the former boundary event missing while setting `nextBeforeVersion` to null. The transcript then appears complete although a saved event is absent, contrary to ADR-0084 RDS-002. Invalidate/cancel the history page whenever detail/history reloads, and test this ordering against the emitted page.

2. **P2 — Principal switching ignores old read results but does not abort those reads.** `packages/compiler/src/customer-requests-presentation.ts:135-162` uses `alive` and epochs to suppress late state updates, yet every list/detail/history fetch is created without an `AbortSignal`; the unmount cleanup starts no abort. Reproduce by holding Customer A's list or detail GET and selecting Customer B: the A request remains pending until the harness releases it. The existing late-response test proves isolation of rendered state, but ADR-0084 SEC-005 explicitly requires aborting reads on principal switch. Bind read requests to abort controllers and abort on principal change/unmount, while retaining the existing late-result guards; add a focused cancellation assertion.

3. **P2 — Mobile route and editor transitions do not restore keyboard focus.** `packages/compiler/src/customer-requests-presentation.ts:163-166` changes route/editor state without a focus target, and `:215-217` hides the list panel on detail/form routes at 800px while showing new controls. Reproduce at 390px using Tab and Enter on a request card or **New request**: the activated control becomes hidden or is replaced, but focus is not moved to the detail Back button, heading, or first form field. Returning from detail likewise has no restored list target. ADR-0084 UXR-003 requires focus restoration and keyboard navigation; the current test at `packages/compiler/test/customer-requests-presentation.test.ts:925-929` only checks that one Tab lands on some button/select. Add explicit route/editor focus handling and an emitted-page keyboard test that checks the focused target after forward and back transitions.

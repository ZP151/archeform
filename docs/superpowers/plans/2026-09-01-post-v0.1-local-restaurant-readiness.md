# Post-v0.1 Local Restaurant Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` (recommended) or
> `superpowers:executing-plans` to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give one to five invited technical evaluators a supported,
credential-safe, repeatable local path from a clean checkout to an edited,
published, compiled, verified, operated, and fully cleaned Restaurant product.

**Architecture:** Keep every delivered product and platform contract unchanged.
Add a Node-built-in toolchain/local preflight, a read-only two-lane GitHub CI
workflow, and a cross-platform orchestration runner that consumes the existing
Compose, Workbench, Control Plane, compiler worker, Restaurant V3 compiler, and
preview boundaries. The real Home template Playwright journey is the product
acceptance authority; CI is deterministic regression evidence only.

**Tech Stack:** Node.js `22.11.0`, pnpm `9.0.0`, Node built-ins, GitHub Actions,
Docker Compose, Playwright `1.51.1`, Axe Playwright `4.12.1`, the existing
TypeScript/pnpm/Turbo workspace.

## Global Constraints

- Preserve mutable Draft -> immutable Published Revision -> immutable
  Compilation; compilers never consume a mutable Draft.
- Keep Node support exactly `>=22.11.0 <23`, select local Node `22.11.0`, and
  execute exactly pnpm `9.0.0` through Corepack.
- Do not add a package, change `pnpm-lock.yaml`, change a Docker image, or change
  the existing Compose topology.
- Keep Application Graph V1/V2/V3, Product Recipe V1/V2, Snapshot V1/V2,
  capability, API, generated Restaurant runtime, and existing Compose contracts
  byte-compatible and unchanged.
- Never print or persist credentials, environment values, raw prompts, raw
  provider responses, request bodies, or generated secret values.
- Bind every service and generated preview through the existing loopback and
  isolation controls; no cloud, hosted, domain, deployment, production-payment,
  identity, tenant, provider, or repository-release action is authorized.
- Use focused RED/GREEN for executable behavior. U2 is an exact configuration
  artifact whose accepted path manifest authorizes no test source; validate its
  absent-file RED, static contract, action provenance, and real GitHub matrix
  execution instead of widening the manifest.
- The controller alone commits and pushes. Never force-push.

## File Responsibility Map

- `.node-version`: exact local Node selector, one line `22.11.0`.
- `scripts/doctor.mjs`: pure doctor evaluation plus a thin CLI boundary.
- `scripts/doctor.test.mjs`: dependency-injected Node tests for every doctor
  success, failure, usage, and redaction rule.
- `package.json`: only the accepted `doctor`, `doctor:toolchain`, and
  `accept:local` command mappings.
- `.github/workflows/ci.yml`: read-only Node `22.11.0`/`22.x` regression matrix.
- `docs/third-party-sources.md`: exact action repository, tag, commit, license,
  role, and verification commands.
- `scripts/local-product-acceptance.mjs`: run identity, safe in-memory inputs,
  orchestration, interruption handling, and cleanup accounting.
- `scripts/local-product-acceptance.test.mjs`: injected command/port/signal
  tests for the runner.
- `e2e/restaurant-template-acceptance.spec.ts`: real Home template product
  journey with no request interception.
- `README.md`: evaluator Quick start using only the accepted command surface.
- `docs/acceptance/post-v0.1-local-restaurant-readiness.md`: bounded safe
  acceptance evidence; no secret or raw-model material.
- `docs/superpowers/ledgers/2026-08-31-post-v0.1-local-restaurant-readiness.md`

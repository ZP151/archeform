# External business-logic portfolio

**Research date:** 2026-07-30
**Decision:** Which public, fixed-reference projects should inform Factory-owned
capability packages, a bounded direct dependency, or replaceable provider
adapters for a broad profile portfolio?

This is a public-evidence research memo, not a dependency, source-copy, or
provider approval. The Application Graph remains Factory Pilot's source of
truth: a capability may contribute bounded Page, Domain, Policy, Flow,
Integration, and Experience projections only to a Draft; only a Published
Revision may compile. See [the platform boundary](../architecture/application-graph-platform.md)
and [the adoption gate](../ecosystem/open-source-adoption.md).

## Reading this portfolio

**Observed facts** are limited to the linked upstream repository, release/tag,
and licence text. A fixed reference is a tag or immutable commit URL. A release
or commit date is an upstream maintenance signal, not a security endorsement.
**Factory inference** is explicitly labelled and never asserts that an upstream
application is already a reusable Factory module.

Classes are intentionally exclusive:

| Class                                | Meaning in this memo                                                                                                                                           |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Direct dependency candidate          | A small published library may be pinned behind a Factory adapter after normal dependency review.                                                               |
| Selective source-vendoring candidate | The licence evidence is permissive enough to consider a narrowly scoped fragment, but only after a separate governed source study; no source is approved here. |
| Provider adapter candidate           | An external product may be reached only through a Factory-owned contract, fixtures, and conformance tests.                                                     |
| Architecture-only                    | Read public behaviour and boundaries; independently write Factory code.                                                                                        |
| Excluded                             | Do not copy, package, link, embed, or run it in a Factory profile under the current policy.                                                                    |

`F`, `B`, and `D` below mean the isolatable **frontend**, **backend/workflow**,
and **data/ledger** concerns respectively. They are proposed Factory seams, not
instructions to copy upstream source. The Restaurant audit already proves a
small native slice (session, menu, cart, simulated payment, kitchen, cashier,
inventory, audit); it also records gaps in configurable modifiers, reservation,
identity, settlement, printers, realtime, and offline operation. [Audit](../audits/restaurant-ordering-requirements-audit.md)

## Promotion requirements and blockers

No class above bypasses the existing source-intake gate. A candidate is
promotable only after all of the following are attached to its own review:

1. **Exact source snapshot.** Record canonical repository, immutable SHA (or
   released tag resolved to SHA), retrieval date, exact paths/line ranges, and
   excluded paths. Snapshot research stays quarantined; it is never imported
   by runtime code.
2. **Licence and notices.** Link licence text at the snapshot, obtain a
   documented compatibility decision, retain required copyright/licence/
   third-party notices, and identify trademark/asset/data restrictions. An
   unknown, custom, GPL/AGPL, source-available, or reciprocal result blocks
   copying/embedding until an explicit governance decision changes policy.
3. **SBOM and security.** Generate dependency and transitive SBOM, provenance,
   licence, vulnerability, secret, and malware scans. Resolve or formally
   accept findings before a published package is pinned.
4. **AST/source review.** Run licence and security AST scans on each proposed
   source fragment; reject credentials, telemetry, network side effects,
   dynamic evaluation, arbitrary file/process access, unbounded SQL, user
   URLs, embedded migrations, and unsupported generated code.
5. **Factory ownership and tests.** Write a Factory-owned interface, fixtures,
   schema/semantic validation, deterministic compiler tests, adapter or
   provider conformance tests, failure tests, and a removal/replacement path.
   Prove no adapter can mutate a Published Revision, bypass PolicyModel/audit,
   persist raw AI material, or make an external data model authoritative.
6. **Immutable adoption evidence.** Add the approved package/version/digest,
   notices, and focused acceptance evidence to a Published Graph compilation;
   upgrades are new reviewed locks, never mutable Draft drift.

Current blockers: the composition kernel must remain parameterized and
collision-safe; real payment, identity, printer, realtime, offline-write,
healthcare, accounting, and provider contracts each need dedicated security or
regulatory review; and no product in the excluded class has a path to source
reuse under the current policy. This directly affects roadmap sequencing:
native shared contracts first, vertical adapters second, optional providers
last.

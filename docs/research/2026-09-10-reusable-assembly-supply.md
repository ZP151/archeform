# Reusable Assembly Supply: Public-Source Shortlist

Date: 2026-09-10.

Status: desk research only; no package, source, asset, provider, model, or
cloud service was installed, downloaded, activated, or adopted.

## Decision investigated

Which public, reusable supplies can let Archeform select and configure a
reviewed assembly for more application types, instead of regenerating each UI
and interaction from scratch? This is a supply and integration study, not
evidence that any candidate produces a complete working application. A source
or material count is never a count of deployable applications.

The approved Archeform reuse order remains: approved registries, recipes,
Workbench assets, generated-project templates, then pinned source studies.
The August 12 inventory found no approved external registry item and recorded
ADR-0010's rejection of direct shadcn/Radix copying for that wave. Nothing in
this research changes that decision or authorizes an external dependency.

## Evidence handling

All observations below were made from official documentation, official
repositories, and project pages on 2026-09-10. Repository-head SHAs are
reproducible observations only; adoption must choose a
published package version or a full commit SHA and retain required notices.

### Current local assembly baseline

This is a measured local inventory, not an external supply admission. The
current registries contain 15 UI primitives, 11 UI patterns, 19 generated UI
entries, 15 Restaurant screen recipes, and 27 capability assets. The pinned
`lucide-static` 0.468.0 package contains 1,544 SVG files, but the accepted
generated emitter allowlist is limited to the Restaurant set plus seven
approval icons. The 1,544-file count is available material, not 1,544
consumer-supported assets. New admissions must expand the approved allowlist
with bindings, tests, provenance, and license evidence rather than exposing an
entire upstream catalog to a model.

## Prioritized three-source future-admission list

1. **TanStack Table 9.2.4 for catalog and task-list blocks**: perform one
   isolated record-workspace experiment behind
   an Archeform adapter. Compare it with current generated assets for binding
   correctness, accessibility, SSR/client boundaries, bundle cost, and the
   amount of hand-written renderer code.
2. **FullCalendar React 7.1.0 with Standard plugins for calendar blocks**:
   perform one isolated appointment-calendar
   assembly that keeps slots, availability, authorization, and persistence in
   the Graph/lifecycle boundary. Feature tests must demonstrate React 19/Next
   15 behavior.
3. **Openverse reviewed-media intake for large photo/content supply**: assess a
   server-side, rate-limited review queue that records an individual item's
   source landing URL, creator, license/version/URL, supplied attribution,
   verification outcome, and availability check. Limit first admission to CC0,
   public-domain, or individually approved licenses. This is not a generated
   app dependency, a bulk import, or automatic model-selected downloading.

DiceBear Core 10.7.0 remains a smaller, deterministic future candidate for
CC0-safe profile/assignee placeholder styles; it is not a substitute for a
general photo/content index.

Before any of those source admissions, define an Archeform-owned registry
manifest using the shadcn registry's useful concepts: a reviewable item payload,
declared closure, and immutable source reference. That is an internal contract
decision, not an admission of shadcn source or tooling.

## Constraints and non-decisions

- The public source counts in this memo describe supplied components, styles,
  icons, hooks, or releases. They do not demonstrate a count of applications
  that Archeform can produce or host.
- No source removes the need for a complete Graph definition, data lifecycle,
  authorization, tenant isolation, a publish/immutable-compilation boundary,
  or hosted delivery.
- No broad installation, code copying, third-party runtime request, provider
  account, commercial purchase, or external asset download is recommended.
- The three proposed experiments touch compiler/runtime and stable Graph/UI
  contracts. Under `docs/tech-governance.md`, PM must dispatch a Tech Lead ADR
  and the founder must explicitly accept it before implementation.

## Machine-readable intake record required for any future admission

Each candidate needs one immutable JSON (or equivalent Graph-adjacent) intake
record before it can be made selectable. Required fields:

| Field                                                                                                                         | Why it is required                                                                                                                              |
| ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `candidateId`, `displayName`, `kind`                                                                                          | Stable identity and classification: registry protocol, behavior engine, block, icon set, or media style.                                        |
| `upstream.repositoryUrl`, `publishedPackage`, `publishedVersion`, `sourceCommit`, `observedAt`                                | Reproducible origin. Package version and source commit must not be silently replaced by a branch tip.                                           |
| `filesOrMaterialCount`, `countDefinition`, `workingApplicationCount`                                                          | Makes explicit what is being counted; set `workingApplicationCount` to `null` unless independently evidenced.                                   |
| `license.codeSpdx`, `license.assetSpdx`, `license.noticeText`, `license.attribution`, `license.restrictions`, `license.owner` | Keeps code and supplied media separate. `owner` identifies the upstream copyright/asset owner, never Archeform merely because it is selectable. |
| `dependencyClosure`, `runtimeCompatibility`, `networkBehavior`, `storageBehavior`                                             | Allows review of package, Next/React, server/client, credential, and data-boundary impact.                                                      |
| `graphBindings`, `assemblyRole`, `excludedFeatures`, `sourceStudyUrl`                                                         | States the exact behavior supplied and preserves Graph as the authority.                                                                        |
| `securityReview`, `accessibilityEvidence`, `testEvidence`, `approvalAdr`, `founderDecision`, `admissionStatus`                | Prevents a model from selecting a source that has only been discovered or studied.                                                              |
| `asset.allowlist`, `asset.licensePerItem`, `asset.noticeOutput`, `asset.sanitizationHash`                                     | Required for icons, SVGs, illustrations, and style definitions; a library-level license is insufficient when materials differ.                  |

An assembly planner may choose only records with `admissionStatus: "approved"`
and an accepted version/source reference. It must include the matching notices
in generated output where the asset license requires them.

# Permissive profile-component intake

**Research date:** 2026-08-01
**Decision investigated:** which small TypeScript/Node/React dependencies or
narrow external-provider adapters can add reusable, non-authoritative building
blocks to Factory-generated applications across the 108 documented Profiles.

## Method and decision rules

This is public-source desk research only. It was checked against
`ecosystem/portfolio/2026-07-30-external-business-logic.json`,
`2026-08-01-capability-supply-expansion-source-matrix.md`,
`2026-08-01-second-capability-supply-matrix.md`, and
`2026-08-01-restaurant-and-profile-candidate-intake.md`. None of the source
repositories or packages below is a prior candidate by name/repository. Whole
vertical applications were excluded. In particular, this does not repeat the
existing candidates for money (`Dinero.js`), calendar, CSV/XLSX, upload,
routing, analytics provider, or feature-flag provider.

**Observed facts** are limited to the linked official repositories, package
registries, and project documentation, checked on the research date. Release
dates and adoption figures are maintenance signals, not security approval.
**Recommendations, rankings, classifications, Graph boundaries, and fixtures**
are Factory inferences. No item is installed, Golden, approved, or represented
as safe to use.

### Common intake gate

Before any use, pin an exact published package version and lockfile integrity,
or a signed release tag plus immutable commit/image digest; collect an SBOM and
transitive licence/NOTICE inventory; verify package provenance where offered;
and retain the upstream licence/NOTICE. Provider adapters additionally require
a Factory-owned contract, local fake, deployment-secret reference, and an
outage mode. A compiler may consume only a published immutable Compilation;
neither an upstream configuration nor a provider response becomes Graph truth.

## Cross-candidate inference and boundaries

The evidence supports small, adapter-shaped dependencies more strongly than any
new application platform. The most reusable additions are calculation,
authentication ceremony/client, document/media interchange, scanning/encoding,
search and inbound-email processing. Provider-backed tax, geocoding and release
gates should remain optional because their public source licences do not cover
service terms, map data, credentials, or operating burden.

No candidate justifies a new mutable source of truth. The recurring product
decision is to add a Factory-owned typed seam and its fixtures first, then
decide whether exactly one implementation is worth pinning. This preserves
Draft -> Publish -> immutable Compilation and prevents generated applications
from persisting upstream library/provider models.

## Ranked 10-item Foundry batch

The ranking maximises distinct capability coverage across the existing
100-plus Profiles while favouring small components over multi-service
operations. It is a proposed research queue, **not** an approval or install
list.

| Rank | Candidate | Why this batch order; first Factory-owned deliverable |
| ---: | --- | --- |
| 1 | `big.js` | Money calculation affects commerce, invoices, expenses, subscriptions, compensation and reporting. Define decimal/rounding contracts and property fixtures first. |
| 2 | `openid-client` | Reusable SSO boundary across customer, workforce, marketplace, care-admin and B2B Profiles. Publish neutral OIDC callback/session contracts and a fake. |
| 3 | SimpleWebAuthn | Adds modern sign-in UX without choosing an identity server. Build passkey ceremony projections and origin/replay fixtures. |
| 4 | `sharp` | Secure media derivatives improve catalog, property, inspection, support and evidence flows. Build a quarantine-to-derivative manifest contract. |
| 5 | `fast-xml-parser` | XML is a common enterprise interchange gap across catalog, supplier, order and invoice inputs. Define a hardened, schema-bound import contract. |
| 6 | Orama | Search serves almost every operational Profile while remaining a derived read model. Build tenant-filtered index/query fixtures. |
| 7 | MailParser | Opens a safe inbound-email boundary for support, CRM, procurement, approval and incident workflows. Deliver a hostile-message parser and canonical message-envelope fixture. |
| 8 | `bwip-js` | Generates reusable labels, tickets, receipts and asset/shipment identifiers. Deliver approved-symbology render fixtures and notice inventory. |
| 9 | `@zxing/browser` | Complements generation with secure scanning for warehouse, event, restaurant, delivery and asset journeys. Deliver untrusted-scan/idempotency fixtures. |
| 10 | `flagd` | A deployment-only gate can safely limit rollout blast radius across generated applications, after a strict feature-gate contract and default-off fake exist. Compare against, rather than duplicate, Flagsmith. |

### Deferred from the batch

`TaxJar` is legally/operationally sensitive and its client is stale; `Pelias`
is a multi-service/data-operation commitment; `web-push` has a stale release;
Apache Arrow requires an explicit aggregate-exchange use case; and Yjs requires
an explicit decision to support ephemeral collaboration before a transport is
selected. They remain research candidates, not recommendations to install or
operate.

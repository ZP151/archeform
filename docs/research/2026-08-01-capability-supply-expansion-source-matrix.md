# Capability supply expansion source matrix

**Research date:** 2026-08-01
**Decision investigated:** which twenty additional public packages and projects
can extend the 100+ Profile roadmap without making an external runtime, data
model, or workflow authoring format authoritative.

## Scope and method

This is a public-source desk-research memo. It was cross-checked against
`ecosystem/portfolio/2026-07-30-external-business-logic.json` and the two
2026-08-01 ecosystem reports. None of the twenty candidates is an existing
Portfolio source record. Facts below are observed from the linked project,
licence, release, or official documentation pages on 2026-08-01. Star/fork,
release, and stated cadence signals are prioritisation signals only, not
security or suitability certification.

### Common fixed-reference and reuse gates

| Classification             | Required fixed reference and reuse boundary                                                                                                                                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Direct dependency**      | Pin the published package version, package-manager integrity hash, and transitive SBOM; retain licence/NOTICE material; add a focused Factory conformance test. The package may implement presentation or bounded calculation only.               |
| **Provider adapter**       | Pin server/image and client-SDK versions (or immutable image digest), API version, and local fake/contract fixtures. Credentials and provider configuration stay in deployment metadata; provider state is a projection, never Graph truth.       |
| **Selective-source study** | Pin tag/commit SHA, licence file, and the precise directory/file scope before inspection. No source is copied by this classification. Any future port needs a separate source-study ledger, attribution, Factory-owned tests, and a removal path. |
| **Reference-only**         | If comparison work is needed, pin only a public tag/SHA and record feature vocabulary. No package, image, runtime, or source fragment may be incorporated.                                                                                        |

## Inferences and recommended intake order

The following conclusions are inferences, not upstream claims:

1. **Prioritise a closed scheduling kernel before selecting a scheduling
   product.** `rrule` supplies recurrence expansion only; Timefold supplies
   non-authoritative optimisation only. Together they support booking,
   staffing, routes, and classes while Factory keeps availability, holds,
   commitments, and approval facts in the Graph.
2. **Make rich-content, dynamic-form, collection-view, upload, and PDF
   outputs compiler-owned projections.** Lexical, SurveyJS, TanStack Table,
   Uppy, and pdf-lib remove repeated UI plumbing across many Profile clusters,
   but none should serialize its own state into Factory models.
3. **Add providers only through narrow contracts and local fakes.** Cerbos,
   LiveKit, GraphHopper, Flagsmith, Timefold, and Superset have useful service
   boundaries. Their configuration, credentials, and replacement concerns are
   deployment concerns, not a Draft input or Compilation truth.
4. **Use Fineract and Wagtail as comparative studies, not implementation
   sources.** Their value is independent vocabulary for finance and structured
   content. A permissive licence does not permit copying an application model
   wholesale or making it canonical.

No finding changes the established platform decision that Draft -> Publish ->
immutable Compilation remains the only path to generated runtime behaviour.
Accordingly, `docs/market-validation.md` was not changed.

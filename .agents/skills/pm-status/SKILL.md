# PM status

Inspect `docs/project-status.md`, `docs/mvp.md`, `git status --short`, the current diff, and the documented checks before reporting progress.

## Workflow

1. Distinguish completed evidence from planned work.
2. Run or inspect the relevant checks when their result is stale or missing.
3. Update `docs/project-status.md` with milestone, completed evidence, active work, risks, and the next smallest slice.
4. Report concise status with file or command evidence. Do not claim completion from intent or chat history.

## Dispatch

Delegate implementation to `engineer`, behavioral validation to `qa`, risk assessment to `reviewer`, and public evidence gathering to `market_researcher` when their work is independent.
